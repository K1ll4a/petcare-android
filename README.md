# PetCare — Android

Kotlin + Jetpack Compose, minSdk 26 (Android 8.0), targetSdk 35.

## Как открыть и запустить

1. Android Studio (Ladybug или новее) → **Open** → папка репозитория.
2. Дождаться синхронизации Gradle, запустить конфигурацию `app` на эмуляторе с API 26+.
3. Тесты: `./gradlew :app:testDebugUnitTest`.

### Откуда берутся данные

Переключается в `app/src/main/java/com/petcare/app/AppContainer.kt`, объект `DevConfig`:

| Настройка | Значения | Зачем |
|---|---|---|
| `DATA_SOURCE` | `FAKE` (по умолчанию) / `SERVER` | тестовые данные без сервера или petcare-backend |
| `FAKE_SCENARIO` | `NORMAL`, `EMPTY`, `ERROR`, `SLOW` | пустой список, ошибка загрузки, медленный ответ (3 с) |
| `FAKE_SAVE_MODE` | `OK`, `SERVER_ERROR`, `NO_RESPONSE` | сохранение: успех, ошибка сервера, ответ не пришёл |
| `BASE_URL` | `http://10.0.2.2:8000` | сервер на компьютере, где запущен эмулятор |

`SERVER`: запустить petcare-backend (`docker compose up --build`). Приложение временно входит тестовым
пользователем `anna@example.com` из seed сервера (`DevLoginTransport`) — до экрана входа Mobile №1 (задача #13).

## Задача #14: что сделано

- **Пространство в каждом запросе.** Питомцы: `GET/POST /spaces/{space_id}/pets`. Профиль: `GET /pet/{id}` с проверкой,
  что `space_id` питомца совпадает с выбранным. Задачи: `GET /task?space_id=…&pet_id=…`.
- **Отправка на сервер:** создание `POST /spaces/{id}/pets`, изменение `PATCH /pet/{id}`, задачи — см. «Допущения».
- **Аллергии и непереносимости** — отдельные поля в форме и в профиле.
- **Срок задачи с поясом пространства:** «сегодня, 20:00» + «Europe/Moscow, UTC+03:00»; ответственный и состояние на карточке.
  Неверный пояс (например, `Mars/Olympus`) — сообщение об ошибке вместо сроков, сохранение задач блокируется. В UTC не подменяется.
- **Ручное обновление** («Обновить» или свайп вниз) перечитывает список питомцев, профиль и задачи; при ошибке старые данные
  остаются с пометкой «Данные не обновлены».
- **Сохранение:** «Сохраняем… ждём ответ сервера», кнопка недоступна; «✓ Сохранено» — только после ответа.
  Ошибка 422 — подсветка полей. Нет ответа — «неизвестно, сохранились ли изменения», данные перечитываются.
- **Поздние ответы:** каждое переключение пространства/питомца отменяет прошлые запросы, а их результаты отбрасываются.
  403 «нет доступа» — данные этого пространства убираются с экрана, остальные пространства остаются.

### Допущения

- **Сохранение задач.** На сервере ещё нет методов создания и изменения задач (задача Backend #11). Приложение
  отправляет `POST /spaces/{space_id}/tasks` и `PATCH /task/{task_id}` с полями `pet_id, task_name, responsible_id,
  is_daily, date_time` (unix), а для ежедневной ещё `start_date` и `local_time` в поясе пространства. Пути — в `TaskEndpoints`,
  поля — в `JsonCodec.taskBody`. Если #11 выберет другие — правятся эти два места. Пока #11 не готова, проверять задачи — в режиме `FAKE`.
- **Макеты UI/UX** (задача #15) ещё в работе — экраны временные, вид будет по макетам.

### Сборка в среде разработки ассистента (шаг 1)

`./gradlew` здесь не собирается: `Plugin [id: 'com.android.application', version: '8.7.3'] was not found` — в среде нет
Android SDK и закрыт доступ к dl.google.com, repo.maven.apache.org и plugins.gradle.org. Код без Android и тесты собраны
компилятором Kotlin напрямую — результаты в [docs/test-results-task14.md](docs/test-results-task14.md).
**Compose-экраны, ViewModel, Activity и OkHttpTransport нужно собрать в Android Studio.**

## Демонстрация для QA (задача #14)

Режим `FAKE`, сценарий `NORMAL`. В тестовых данных три пространства: «Семья» (Europe/Moscow), «Дача» (Asia/Yekaterinburg),
«Сломанный пояс» (`Mars/Olympus`).

1. **Профиль.** «Семья» → Tom: аллергии «курица» и непереносимости «молоко» — отдельными строками.
2. **Задачи.** У каждой задачи срок, пояс «Europe/Moscow, UTC+03:00», ответственный и статус (предстоит, просрочено, выполнено, пропущено, отменено).
3. **Два пространства.** Пространство ▾ → «Дача»: сразу пропадают данные «Семьи», видны Мурка и Шарик, пояс «Asia/Yekaterinburg, UTC+05:00».
4. **Два питомца.** Мурка ↔ Шарик: задачи и профиль меняются, чужие не видны.
5. **Пустой список.** «Семья» → Кеша: «У питомца пока нет задач».
6. **Создать питомца.** «+ Питомец» → без имени «Сохранить» → подсветка поля. Имя, вид, аллергия → «Сохраняем…» → «✓ Сохранено» → «К списку»: питомец выбран.
7. **Изменить питомца.** «Изменить» → очистить аллергию → сохранить → в профиле «Аллергии: не указано».
8. **Создать задачу.** «+ Задача» → название, ответственный, «Ежедневно», 20:00 → сохранить → задача в списке с поясом пространства.
9. **Изменить задачу.** Нажать на предстоящую задачу → сменить время и ответственного → сохранить → список обновлён.
10. **Неверный пояс.** «Сломанный пояс»: профиль виден, вместо задач — ошибка про `Mars/Olympus`, «+ Задача» скрыта.
11. **Ошибка.** `FAKE_SCENARIO = ERROR` → «Нет соединения с сервером» + «Повторить», приложение не закрывается.
12. **Медленный ответ.** `SLOW` → загрузка 3 с, во время неё можно переключать питомцев; быстро нажать Tom → Рекс → Tom → Рекс: в итоге только данные Рекса.
13. **Сохранение без ответа.** `FAKE_SAVE_MODE = NO_RESPONSE` → сохранить → «неизвестно, сохранились ли изменения», после перезагрузки видно серверное состояние.
14. **Ошибка сервера при сохранении.** `SERVER_ERROR` → «Ошибка на сервере», «Сохранено» не появляется.
