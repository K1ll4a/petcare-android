# Задача #23: серверные профили и задачи на Android и iOS

Ветка: `feature/server-pets-tasks` (от `feature/android-ios`). Исполнитель: Mobile №2.
Контракт: `petcare-backend/docs/API.md` версии 1.2 и `docs/task20_contract.md` (12.11.2026),
сверено с кодом сервера `app/routers/tasks.py`.

## Что изменено в общем коде (`shared/src/commonMain`)

| Было (допущение недели 2) | Стало (окончательный контракт) |
|---|---|
| `PATCH /task/{id}` | `PATCH /tasks/{task_id}` |
| поля `task_name`, `responsible_id`, `is_daily`, `date_time` (unix) | `task_title`, `assignee_id`, `recurrence` (`once`/`daily`) |
| срок разовой — unix-число | `scheduled_at` — ISO 8601 с `Z` (сервер отклоняет время без пояса, 422) |
| ежедневная — `date_time` + `start_date` + `local_time` | только `start_date` + `local_time` в поясе пространства; срок считает сервер |
| изменение отправляло все поля, включая `pet_id` | `PATCH` — **только изменённые поля**; `pet_id`/`space_id` не отправляются никогда |
| изменение питомца — все поля | `PATCH /pet/{id}` — только изменённые; очищенное поле — `null` |
| id из ответа: `id` | ответ создания/изменения — объект задачи с `task_id` (не элемент списка) |
| — | в элементе списка читается новое поле `completion_id` |
| `TaskEndpoints` с пометкой «предположение» | удалён: пути взяты из контракта |

Файлы: `data/remote/RequestBodies.kt` (тела запросов), `data/mapper/Mappers.kt` (форма → поля контракта),
`data/remote/PetCareApi.kt` (пути), `domain/repository/Repositories.kt` (изменение получает исходные данные формы),
`presentation/edit/*` (форма помнит исходное состояние, питомца у существующей задачи сменить нельзя,
ошибки полей `task_title`, `assignee_id`, `scheduled_at` подсвечиваются), `data/repository/ServerPetCare.kt`.

Область запроса: питомцы — `/spaces/{space_id}/pets`, профиль — `GET /pet/{id}` с проверкой `space_id`,
задачи — `GET /task?space_id=…&pet_id=…`, создание задачи — `/spaces/{space_id}/tasks`. Ответ с питомцем или
задачей другого пространства не показывается. После подтверждённого сохранения экран перечитывает
профиль и задачи с сервера; до ответа «Сохранено» не показывается, без ответа — «неизвестно, сохранились ли изменения».

Ошибки сервера показываются текстом `message`: `400 bad_request` (ответственный не в пространстве,
смена питомца), `409 task_completed` (выполненную разовую задачу менять нельзя), `422` — по полям формы.

## Подключение к серверу

`serverPetCareRepository(baseUrl, tokens)` в `data/repository/ServerPetCare.kt` собирает серверный репозиторий
для обеих платформ (Ktor: OkHttp на Android, Darwin на iOS). Его нужно поставить в `AppContainer` вместо
`SessionPetCareRepository`, когда **серверный вход Mobile №1** будет выдавать токен (`TokenProvider`).
До этого приложение работает в демо-режиме: без токена сервер отвечает 401 на любой запрос питомцев и задач.
Адрес: эмулятор Android — `http://10.0.2.2:8000`, iOS Simulator — `http://localhost:8000`.

Новые тесты: путь `PATCH /tasks/{id}` и только изменённые поля; `scheduled_at` с `Z` в поясе пространства;
ежедневная задача без `scheduled_at`; смена повторения в обе стороны; ответ с `task_id`; `400`/`409` с текстом
сервера; запрет смены питомца на клиенте и в фейке (как на сервере); `completion_id`; частичный `PATCH` питомца;
вторая правка формы считается от сохранённого сервером состояния.

Полная Gradle-сборка в среде ассистента невозможна: доступ к Maven Central, Google Maven и Gradle Plugin Portal
закрыт политикой сети. Поэтому итог сборки и тестов — по CI.

## Шаги проверки для QA

**Сейчас (демо-режим, обе платформы):**

1. Войти `grisha@example.com` / `demo12345` → «Семья» → Tom.
2. Открыть предстоящую задачу, сменить только время → «Сохранить» → «Сохраняем…», затем «✓ Сохранено»; в списке новое время.
3. В той же форме чип питомца недоступен: питомца существующей задачи менять нельзя.
4. Профиль Tom → очистить «Аллергии» → сохранить → «Аллергии: не указано».
5. «Пространства» → «Дача»: только Мурка и Шарик, задачи «Семьи» не появляются.
6. `DevConfig.FAKE_SCENARIO = EMPTY / ERROR / SLOW`: пустой список, ошибка с «Повторить», загрузка;
   при `SLOW` быстро переключить питомцев и пространства — остаются данные последнего выбора.
7. `FAKE_SAVE_MODE = SERVER_ERROR / NO_RESPONSE`: «Сохранено» не появляется.

**После серверного входа Mobile №1** (сервер `docker compose up --build`, аккаунты `anna@example.com`,
`ivan@example.com`, `oleg@example.com`, пароль `demo-password`):

1. Android — Анна, iOS — Иван, оба в «Семье».
2. Анна меняет профиль питомца и создаёт задачу → Иван нажимает «Обновить» → видит изменения.
3. Иван меняет ответственного → Анна обновляет → видит нового ответственного.
4. `docker compose restart api` → обновить на обоих устройствах → данные на месте.
5. Олег («Дача») не видит питомцев и задач «Семьи»; переключение пространств у Анны не показывает чужие задачи.
6. Остановить сервер → сохранить изменение → ошибка, «Сохранено» не появляется.
