# [Mobile] Модели питомца и задачи, тестовые данные, временный главный экран

Ветка: `feature/week1-pet-task-models` → `main` (или общая ветка Mobile)
Ревьюер: Mobile №1

## Что сделано

1. **Модели данных** (FR-04, FR-06, FR-07, FR-09, FR-10)
   - `data/remote/dto/Dtos.kt` — DTO ровно по контракту Backend (`task_id`, `task_name`, `pet_id`, `date_time`, `responsible_id`, `is_daily`; `pet_id`, `pet_name`, `pet_type_id`).
     Запрошенные у Backend поля (`status`, `occurrence_date`, `completed_*`, `responsible_name`, `is_active`, `space_id`, `allergies`…) — nullable, разбор не падает, пока их нет.
   - `domain/model` — `Pet`, `Task`, `TaskItem` (экземпляр для списка), `TaskStatus`, `RepeatType`, `Space` (ради часового пояса).
   - `data/mapper/Mappers.kt` — единственное место преобразования DTO → домен.
2. **Тестовые данные** — `assets/test_data.json` в формате Backend: 3 питомца (один без задач), 9 задач, покрыты все статусы, разовые и ежедневные, отключённое расписание, задача в «голом» формате Backend без статуса.
   Даты автоматически сдвигаются на «сегодня», чтобы данные не устаревали.
3. **Фейковый репозиторий** — `FakePetCareRepository` реализует `SpaceRepository`, `PetRepository`, `TaskRepository`. Сценарии `NORMAL / EMPTY / ERROR / SLOW` для проверки состояний (переключаются в `AppContainer`).
4. **Временный главный экран** — выбор питомца, его особенности, список задач со статусами; состояния загрузки, пусто, ошибка + «Повторить», pull-to-refresh.
5. **Unit-тесты** — 32 теста: маппер, сортировка, часовой пояс, фейк, логика экрана (включая поздний ответ при быстром переключении питомца).

## Решения, на которые стоит посмотреть

- **Статус задачи не считается на клиенте (BR-02).** Если Backend не прислал `status` — показываем «Статус неизвестен», а не вычисляем «просрочено» по времени.
- **Время — в часовом поясе пространства (BR-05)**, не устройства: `SpaceTimeFormatter`.
- **Защита от гонок (FR-19, AC-19):** при смене питомца прошлый запрос отменяется, а ответ для чужого питомца выбрасывается.
- **Логика экрана в `HomeController` без Android-зависимостей**, `HomeViewModel` — тонкая обёртка. Так логика тестируется на JVM.
- Ручной DI в `AppContainer`; на неделе 2 фейк меняется на API-реализацию только там.

## Как проверить

1. Открыть проект в Android Studio, запустить `app` на эмуляторе (API 26+).
2. Переключать питомцев: Tom — все статусы, Рекс — задача без статуса и без имени ответственного, Кеша — пустой список.
3. В `AppContainer` поставить `FakeScenario.ERROR` → ошибка и «Повторить»; `SLOW` → быстро переключать питомцев, чужие задачи не должны мелькать.
4. `./gradlew :app:testDebugUnitTest`.
